# Add a Creature

A mob is a `Player` with AI: `Mob` (`src/creatures/Mob.ts`) extends `Player` (`src/Player.ts`). Copy `src/creatures/Rat.ts` as the simplest template; `Goblin.ts` shows config-driven variants + custom loot.

## Required in the subclass

- `readonly xpValue: number` (abstract).
- `updateAI(targets: Player[]): void` (abstract) — called each frame by `MobUpdateLoop`. Pattern: guard `if (!this.isAlive) return` → tick cooldowns → find nearest living target in aggro range → `updateLastKnown(target)` + `followTargetAStar(...)` → attack in range via `this.dealDamage(target, base)` → else `doWander()`.
- `protected override drawSelf(ctx, camX, camY, tileSize)` (abstract on `Player`) — compute `sx = this.x - camX`, `sy = this.y - camY`, call your sprite draw fn, then `renderMobHealthBar` (and `renderAggroIndicator` if aggro'd). Never override `render`: `Player.render` is sealed and wraps `drawSelf` so the hit flash and status paint land on the figure's own silhouette.
- Constructor: `constructor(tileX, tileY, tileSize) { super(tileX, tileY, tileSize, MAX_HP, SPEED); }` — extract HP/speed/ranges into named module-level constants (CLAUDE.md: no magic numbers).
- `protected override get eyePlacement(): EyePlacement | null` (abstract) — where its eyes are, for the two glints the dungeon's dark shows of a hostile it hides (`DungeonLightingSystem.renderEyeShine`). `EyePlacement` (`src/sprites/eyePlacement.ts`) has two shapes, after how the art turns to its facing:
  - **Views** (`ViewedEyePlacement`) — art drawn as profile / face-on / back, picked by the dominant facing axis. In tiles from the tile's top-left: side (`sideForward` toward the way it faces, `sideHeight`, `sideSpacing`) and facing the camera (`frontAcross`, `frontHeight`, `frontSpacing`); facing away shows none. `frontMirrors` is required: true only when the painter flips the face-on drawing with `facingX` (art drawn only in profile, which keeps showing that profile facing the camera); false for a face-on view it never flips, where `frontAcross` is the offset as painted and must not jump as the facing leans left or right. Read the sprite wrapper's `flipX` rule to decide. Most art stands well above its tile, so heights are usually negative — never guess a one-tile biped's numbers.
  - **Turning** (`RotatingEyePlacement`) — art seen from above and rotated to its facing (spiders). Give the pivot, the eyes in the art's own unturned frame, and the painter's own rotation function (`spiderFacingRotation`, `grotesqueSpiderFacingRotation`) — share it, never re-derive the angle.

  Return `null` for a creature with no eyes to show (a grub, an egg, a prop, a vine) and for states where the head is not up (a skeleton still rising, a bugaboo under its grate, a summon still emerging); `RisingSkeleton` subclasses implement `standingEyePlacement` instead. Derive it from the art's own rig constants where they exist, so it follows the art (`skeletonEyePlacement`, `LICH_EYE_PLACEMENT`, `REMEX_EYES`); otherwise measure it off the render (`npx tsx scripts/verify-eye-shine.ts --png=preview/eye-shine.png` draws every creature with a tenth-of-a-tile grid). Then add the class to `SUBJECTS` in `scripts/verify-eye-shine.ts` (one entry per state that draws differently) — `npm run verify:eye-shine` finds every concrete `Mob` under `src/creatures/`, fails on one with no subject, checks the glints against the drawn body at twelve facings (compass, leaning, diagonal), and fails glints that move between two mirrored facings that draw the same body.

## Optional overrides (all have base defaults)

`coinDropMin/Max`, `displayName`, `description`, `audioTag`, `bodyPartKey`, `mass` (heavier = displaced less in separation), `separationAnchored` (nothing can push it; whatever bumps it, crawlers included, takes the whole push), `collisionRadiusPx` (for a body drawn wider than a tile: measure it from the rendered art, keep it inside both crawlers' melee reach, and see `KrakarenClone`), `isFlying`, `isBoss`, `isHostile`, `requiresEvasion`, `rollLootItems(killer)` for creature-specific drops, `tacticsEligibility` (see below).

## Do not reimplement — inherited helpers

`dealDamage(target, base)` (**use this, not `target.takeDamage()`** — it scales with mob level and sets `attackSoundPending`), `takeDamageFrom` (handles damage tracking, kill credit, loot roll), `followTargetAStar`, `followTargetCollide`, `moveWithCollision` (respects walls), `hasLOS`, `doWander`, `applyMobLevel`, `applyStatus`/`hasStatus`. `setMap()` is injected by the spawner.

Level math goes through `src/creatures/mobLevelScaling.ts` (`hpScaleForLevel`, `scaledDamageForLevel` — or `Mob.scaledDamage` from inside a mob — `scaledCooldownFramesForLevel`, ...). Never write `1 + x * (level - 1)` in a creature, boss or system: the curves carry the multiplier ceilings, and a creature's own arithmetic would escape them. How hard a creature feels is tuned by playtest, not by a gate.

## Tactics traits

Levelled mobs can learn `flank`, `block`, `kite`, `regroup` and `riposte` (`src/creatures/tactics/`; rules are P6 in `docs/difficulty-fairness-rules.md`). A creature opts in by overriding `protected get tacticsEligibility(): readonly TacticsTrait[]`. The default is none, and it **stays none** for bosses, quest NPCs, summons, maze targets, non-combatants, mercenaries and rooted creatures (a rooted mob cannot flank or kite). When a boss or system conjures a creature that is eligible on its own (Miss Quill's krasues), set `mob.isSummon = true` before `applySpawnDifficulty` and it rolls nothing. List only traits your `updateAI` actually acts on — a rolled trait with no behaviour behind it is a promise the fight never keeps.

- Which bodies suit which traits: melee brawlers take `flank`, `block`, `regroup`, `riposte`; pack skirmishers add `kite`; ranged creatures take `kite` (with a `KiteAim` that keeps a friend between them and the player) and `regroup`, never `block`; tiny swarmers take `flank` only.
- `block` needs no creature code — `Mob.takeDamageFrom` rolls the guard and shoves the mob. But while a guard's shove runs, `Mob.moveWithCollision` refuses the mob's own movement. A charger that reads a refused move as a wall hit (and stuns itself, ends its charge, bounces) will misfire on every guard; handle that before listing `block`.
- Movement traits are wired into `updateAI`. `Goblin` is the reference: each frame with a target, call `this.tactics.chooseMove(frame)` (a `TacticalFrame` with `canBreakOff` false mid-swing), walk a `breaksOff` move instead of fighting, walk a flank move as the chase goal, and keep facing the target on arrival. A creature that chases its last sighting with `followTargetAStar` does all of that through two `Mob` helpers: `chooseTacticalStep(target, attackRangePx, canBreakOff, kiteAim?)` (builds the frame, drops the cached route when the answer changes kind) and `walkTacticalStep(move, target)` (walks it, caps a retreat at `TACTICAL_RETREAT_MAX_SPEED` so a fast creature stays catchable, faces the target on stopping) — `RuinsGhoul` is the shortest example. Call `this.tactics.disengage()` when the target is lost. For `riposte`, `if (this.tactics.claimRiposte()) this.attackCooldown = riposteCooldown(this.attackCooldown, swingFramesLeft)` — it cuts only the wait between attacks, never the windup.
- A creature whose body changes mid-life can make `tacticsEligibility` read its current form (`BrindleGrub` flanks as a grub, learns nothing as a Vespa). Traits are still rolled once, at spawn; one the new body is not eligible for goes dormant — dropped from `activeTacticsTraits`, which the rank mark, notices and telemetry read — rather than stripped. Stop asking for tactical moves in that form and call `this.tactics.disengage()` when it changes.
- Traits are rolled at spawn by `applySpawnDifficulty` (`src/core/difficulty/difficultyProfiles.ts`), which every spawn site must call straight after `applyMobLevel`. A system that levels a mob itself (a summon, a quest wave) calls it too.
- Run `npm run verify:tactics` after opting a creature in.

## Registration (all required for every hostile)

1. `src/levels/mobKinds.ts` — add an entry to `MOB_KIND_DEFS`. Its key is the kind (`MobKind` is derived from the keys, so a misspelled kind anywhere is a compile error). Every field is required:
   - `create` — builds the class from the tile (and the look, for a kind with a variant family). A kind that needs extra constructor arguments (an owner, a leash) declares them as typed options: `kind<MyMob, MyOptions>({ create: (tile, _look, _random, options) => ... })` (the full signature is `create(tile, variant, random, ...options)`, where `random` is the spawn context's stream; a kind that rolls anything at construction draws from it, never `Math.random`), and also goes in `KINDS_NEEDING_OPTIONS`; such a kind cannot be named in a spawn table.
   - `threat` — rated by the method in `MobKindEntry`'s JSDoc (base HP × hits per second × damage, normalised so a melee goblin is 1; ×1.5 ranged, ×1.25 area or status). Kind ladders convert counts with it.
   - `role`, and `protected` (`'boss'`, `'boss-add'`, `'quest-critical'` or null). A protected kind is never substituted by a ladder.
   - `prewarm` — the figure rows one spawn draws first, or null.
   - `approach` (optional) — for a figure-drawn kind, the figure each look is drawn as and the row names it walks up to a fight in and opens it with (`ApproachSpec`, `src/sprites/figure/approachRows.ts`). A lead-in that knows a kind is coming, such as the Briar Hollow siege's countdown, warms exactly these, so a kind without it arrives cold there.
   - A creature with several looks uses `lookKind` with a `MobVariantFamily` (`src/core/mobs/mobVariantFamily.ts`) declared beside the class, takes its look as a constructor argument (never picks one itself), draws the figure its look names, and exposes `applyVariant(look)` so a live body can be re-dressed in the shared look. Look-coupled parameters (a weapon's timing) come from the look.
2. Spawn it only through `spawnMob(kind, tile, map, context)` (`src/levels/spawnFunnel.ts`). The context names the encounter (`EncounterId`, `src/levels/encounters.ts`) and the random stream; live play passes `Math.random` (`liveSpawnContext(encounter)`). `npm run check:spawn-funnel` fails on a hostile `new MyMob(` anywhere else in `src/`.
3. Reference it in a level def (`src/levels/level*.ts`): `roomMobs`/`hallwayMobs` (`{ type, chance, minCount, maxCount, minLevel, maxLevel }`), `bossRooms: [{ type }]`, `extraSpawns` (landmark-relative, optional `setup` callback in `SPAWN_SETUP` for post-spawn init like arena binding), or `onMobKilledSpawns`. A gauntlet boss whose room has dressing is matched to it by boss type (`TRASH_GREMLIN_BOSS_TYPE` etc. in `src/systems/bossRooms/BossRoomDressings.ts`), never by its index in `bossRooms`.
4. `src/core/spriteAssets/assetGroups.ts` — add the kind to `MOB_SPRITE_KEYS`, listing the sprite keys it needs (an empty array if it draws procedurally with no sheet). The record is keyed by every `MobKind`, so a kind with no entry fails `tsc`. A friendly creature that never goes through `spawnMob` goes in `FRIENDLY_CREATURE_SPRITE_KEYS` instead.
5. If the sheet is new, add its key to whichever `AssetGroup` covers the context the creature appears in, and make sure every floor that can produce it declares that group — via `LevelDef.spriteGroups` for a spawn-table mob, or via a `SYSTEM_ASSET_REQUIREMENTS` entry (`src/core/spriteAssets/systemAssetRequirements.ts`) for anything a _system_ constructs: a bounty escort, a quest wave, a companion, a mid-fight summon. A creature reachable only through a system is named in no `LevelDef`, so nothing else declares it and its sheet would never be grouped. Background: `docs/asset-management.md`.

### Variety tiers

On a device that lags or drops canvases the game trims looks before smoothness (`docs/asset-management.md`, "Variety tiers"). A new kind takes part by:

- rating `threat` by the method in `MobKindEntry`'s JSDoc, and setting `role` and `protected` (a protected kind is never substituted);
- declaring a `MobVariantFamily` if it has more than one look, so every spawn can share the canonical one;
- getting a row in the ladder of every encounter it joins that declares one (`ENCOUNTER_LADDERS`, `src/levels/encounters.ts`), with a stand-in that encounter already fields at that tier; `npm run gates:assault-residency` checks the siege's;
- being spawned only through `spawnMob`, and in a laddered encounter only after `planEncounterRoster` has resolved the roster.

## Runtime spawning

Any mob added mid-game joins through the scene's roster: `world.roster.add(mob)` (or `ctx.roster.add(mob)` inside a system). That is the only spawn path — it inserts into the list _and_ the spatial grid _and_ hands the mob the scene's map and spell context, and a mob that misses the last of those walks straight through a protective shell. AI only runs within `AI_RADIUS` of players via `roster.grid.queryCircle` unless `requiresEvasion` is set. `CombatSystem.resolveKills` removes dead mobs from the grid.

## Friendly mobs (livestock, militia)

A creature that must be hit by the world's damage pipeline but is not an enemy is still a `Mob`: `Cow` (`src/creatures/Cow.ts`) and `RatkinSoldier` (`src/creatures/RatkinSoldier.ts`) are the examples.

- `isHostile` false. `isPetAttackable` follows it by default; override it false too if the base would say otherwise. Mongo, hirelings, auto-aim, homing missiles and friendly fire then pass it by.
- `takesPlayerDamage(type)` is an allow-list of the crawler damage types that may hurt it (a cow takes only `explosion`, `smush`, `missile` — Space pets it instead of swinging).
- `countsAsKill` false and `paysNoRewards` true, so its death pays no XP (otherwise `resolveKills` pays at least 1), counts toward no achievement and no multi-kill.
- Hostiles only fight what they are handed: an ally that should be attacked is pushed into `ctx.extraTargets` (see `BriarHollowKit.pushAlliedDefenders`). Never set `isDefendTarget` on it — hostiles skip defend targets.
- A soldier is knocked down, not killed: it zeroes out inside its own damage doors, keeps `rendersWhenDead`, and overrides `undoResurrectionForCheckpoint`.
- Any "for every mob" sweep you write must filter on `isHostile` explicitly.

**Hostile-only walkability.** `GameMap.isWalkableForHostile` also honours `BLOCK_HOSTILE_ONLY` (Briar Hollow's gate). Mob movement (`stepThroughWalls`, `findPath(..., forHostile)`, tactical steps) uses it when the mob is hostile; line of sight and spawn checks do not. A custom mover must use the same test, or hostiles walk through the gate.

**Root.** `Mob.root(frames, source)` / `releaseRoot` / `isRooted`: `moveWithCollision` refuses the mob's own steps (knockback still moves it) but it keeps attacking. Unlike `aiHeld`, it does not clear the target. A charger must end its charge when rooted.

**Siege opt-in.** Any mob can fight the village assault without changing its AI: `enlistInSiege(mob, world, seed)` (`src/creatures/siege/siegeCapability.ts`) sets `mob.siegeCapable`; `Mob.siegeStructureMultiplier` (default 1, archers 0) scales its blows on walls; `playStructureStrike(onImpact)` plays the strike on the real swing row; `siegeAdvance(mob)` strikes or takes one flow step when there is nobody to fight. `MobUpdateLoop` consults `mob.siegeDirective` before `updateAI`; a mob that moves itself (Grave Bull, Necromancer) returns true from `ownsSiegeMovement`. A mob that throws at structures instead of swinging (the bomber goblins) offers a `SiegeLobber` from `Mob.siegeLobber`, which makes `lobsAtStructures` true: the march then has it lob at a trebuchet, a defender or the wall in its way from its standoff band, and never walk up to swing.

**Conversion.** A level-15 snare can turn a hostile into an ally: `canBeConverted()` (never bosses or constant-`isHostile` subclasses) plus membership of `CONVERTIBLE_MOB_TYPES` (`src/creatures/convertibleMobs.ts`), which lists only types whose AI is proven against mob targets. `convertToAlly(owner)` flips `isHostile`; every `isHostile` reader must then treat it as an ally, and a rewind reverts it.

## Don't forget

- **Sprite**: see the `add-sprite` skill — you need a sprite sheet + manifest entry + `src/sprites/myMobSprite.ts` draw wrapper.
- **Loot**: automatic via `coinDropMin/Max` + `rollLootItems()`; override the latter for custom drops.
- **XP/kills**: automatic if you use `dealDamage`/`takeDamageFrom` — `CombatSystem.resolveKills` splits XP and emits `mobKilled`.
- **Gore**: blood is automatic. Body-part gore is opt-in: set `bodyPartKey`, add a config in `BODY_PART_REGISTRY` (`src/systems/BodyPartGoreSystem.ts`), and add matching `gore_*` states to the sprite manifest.
- **Sounds**: set `audioTag`, then add a `case` for it in the audio switch in `DungeonScene` (search `audioTag` there). Set `projectileSoundPending` yourself for ranged attacks. See `add-sound`.
- **Y-sort rendering**: free — `RenderPipeline` sorts by `mob.y`.
- **Incurable statuses**: a status in `INCURABLE_STATUSES` (`src/core/combat/StatusEffect.ts`; today only blood vomiting, `BLOOD_VOMIT_STATUS`) survives `Player.clearStatusEffects`, `cureStatuses`, every cure item and service, and a knockout and revive. Only a party death that respawns clears it (`checkpointSnapshot`, `progressForRespawn`). It crosses saves through `src/core/save/bloodVomitSave.ts`, because snapshots rebuilt for a door or floor drop their statuses.
- **Telegraphed attacks**: a new telegraphed attack must satisfy the P2 fairness invariants in `docs/difficulty-fairness-rules.md`, and is gated by `npm run verify:difficulty`.

## Companions and pets

A player-owned creature is a `Mob` with three contracts the base class does not give you. `Mongo` (`src/creatures/Mongo.ts` + `src/systems/MongoSystem.ts` + `src/core/state/MongoPetState.ts`) is the worked example; read those three together before building another. The human's attack cow (`src/creatures/AttackCow.ts` + `src/systems/AttackCowSystem.ts` + `src/core/state/AttackCowState.ts`) is the second: always out once owned, downed and revived rather than killed, and the one companion that taunts.

**Attribution.** A pet must deal damage in its own name — pass itself as the attacker and set `target.retaliateMob = this` — or the mobs it mauls come after the owner standing behind it. Kill credit is then redirected by `Player.xpCreditTarget` (defaults to `this`; a pet returns its owner), which `CombatSystem.resolveKills` maps damage entries through, so the owner keeps the XP exactly as before. `Mob.killedByDealer` holds the literal dealer alongside the credited one, because killer-keyed loot rolls and achievements must still see the pet. Any `takeDamageFrom` override in a boss subclass has to preserve this mapping or it silently drops pet credit.

**Targeting.** `Mob.isPetAttackable` (default `isHostile`) is the pet's target predicate, not `isHostile` directly — it lets a calm creature opt into being prey without becoming hostile to the player. A pet's acquisition must still pass `canNotice`; it is easy to write the one targeting path in the codebase with no perception gate, and a pet that beelines at enemies through walls is what that looks like.

**State outlives the creature object.** A pet that is summoned and dismissed is a new instance every time, so HP, regeneration, level-scaling and any recovery lock live in a plain state object threaded through scene options — never on the `Mob`. Two consequences worth knowing in advance: the accessor a save path or a UI bar reads must distinguish stored HP from live HP (a spent pet is pinned at 1 HP so it can walk home, and an autosave mid-retreat would otherwise record that 1 as health it does not have); and a pet that despawns leaves every mob it provoked holding a `retaliateMob` reference to a creature that never dies, so those references must be cleared both when the retreat starts and when it finishes.

**Taunting.** `Mob.tauntedBy` makes a mob go for a party creature ahead of anyone nearer, with no stepping-in-front exception. It only takes effect while the taunter is a target candidate, so whoever sets `tauntedBy` must set `retaliateMob` to the same creature, and must clear both when the taunt lapses (out of range, out of sight, the taunter down or gone) — a stale `tauntedBy` or `retaliateMob` pins the mob on a creature that is not fighting. `AttackCowSystem` re-evaluates its taunts every frame and releases every reference in `releaseTargeting`; bosses, converted mobs and mobs off limits to allies are never taunted.

**Summoning onto a tile.** Derive the owner's tile from her centre, not `floor(x / TILE_SIZE)` — that is the tile under the sprite's top-left corner, which in a corridor is masonry. Ring-search for a nearby walkable tile, require line of sight from the owner (or the search "solves" a blocked corridor by placing the pet in the room through the wall), and exclude stairwell tiles: `isWalkable` admits them while `Mob.moveWithCollision` refuses to enter one, so the spawn contract has to match the movement contract or the creature lands somewhere it cannot leave. If no tile qualifies, refuse the summon with a message — there is no valid "just use the owner's tile" fallback, because the only way to reach that case is the owner herself standing somewhere unwalkable.

**Leash bands are not self-guaranteeing.** Ordering an engage-persist radius inside a leash-break radius does not prevent yo-yoing: persist is straight-line, the leash is route length, so a mob four tiles away behind a nine-tile detour is simultaneously inside persist and past break. What stops it is dropping the target and holding it off in a ban map with an expiry. Likewise a follow band needs a latched flag, not two thresholds — re-deciding from raw distance each frame stops the pet the instant it crosses the line, the owner's next step pushes it back over, and the sprite vibrates at her shoulder. And a stall detector must measure pixels actually covered, never `isMoving`, which is true for a mob grinding into a wall.

## Hirelings (Meat Shields mercenaries)

A hireling is a player-owned `Mob` like Mongo, but paid for at the Desperado Club's desk and held to a contract. Everything a hire shares lives in one shell; everything that makes it fight differently lives in a kit.

- **`Mercenary`** (`src/creatures/Mercenary.ts`) is the shell: follow band, leash, the aggro scan over `allMobs` (measured from the owner), hurt reactions, low-HP and idle barks, talk, the terminal death phase and fading corpse (`rendersWhenDead`), and drawing. It never decides how to attack.
- **`MercenaryKit`** (`src/creatures/mercenaries/MercenaryKit.ts`) is the interface a kit implements; its header documents the order the shell calls it in. Kits keep their own state, one instance per hireling, built by `createMercenaryKit` (`mercenaryKits.ts`) from a `Record<MercenaryKitId, …>`. Current kits: `cretinGuardKit` (Sledge and Bomo, one kit with a per-hire config), `lancerKit`, `waterMageKit`, `brawlerKit`, `medicKit`, `golemKit`; `basicMeleeKit` and `MercenaryStrike` (`mercenaryStrike.ts`, a committed swing that lands on its drawn impact frame) are the pieces to build a melee kit from.
- **Credit.** Every blow a kit lands goes through `Mob.takeCreditedDamage(damage, merc.owner, type, merc)`: the owner earns the kill, while a guard is judged against the hireling that swung.
- **Projectiles.** A kit hands shots out through `drainProjectiles()`; the shell sorts them into two outboxes: rocks for `RockThrowSystem` (`takePendingThrows`), bolts and waves for `HirelingBoltSystem` (`takePendingShots`). Both drain the whole mob list, so a shot loosed on the frame the hireling dies still flies. Neither lets an ally's shot hurt the party, and `HirelingBoltSystem` also stops at a safe room's threshold.
- **Voices.** The words themselves live in `src/dialog/scripts/mercenaries.ts`, one `NonEmpty<BarkLine>` pool per `MercenaryBarkTrigger`, built with `speakerLines(id).bark(text)` (`src/dialog/line.ts`); `MERCENARY_VOICES` (`mercenaryVoices.ts`) maps each voice to those pools per trigger (`hired`, `idle`, `engage`, `kill`, `low_hp`, `special`, `owner_hurt`, `cat_hurt`, `death`, `talk`, `floor_end`), and a voice with no words carries `grunts` and italic stage directions instead. `MercenaryBarker` owns the per-trigger cooldowns, the global minimum gap, and picking one line of a pool without repeating the last one spoken. Lines are written in the character's voice and are always original. Rendering is unchanged: a bark still shows as a speech bubble over the hireling, not through `Conversation`.
- **Art.** `MERCENARY_ART` (`src/sprites/mercenaryArt.ts`) is the only place a hire's look is chosen: one entry per `MercenaryArtId` with `draw`, `cullMarginTiles`, `headLiftTiles`, `eyes` (its `EyePlacement`), `deathFrames`, optional `goreBodyPartKey` (a figure that comes apart instead of falling over), `prewarm`, optional `prewarmForFight`, optional `gait` (walk phase paced by ground covered) and optional `healthBarLiftTiles`.
- **The system.** `MercenarySystem` spawns the hire behind its owner on the scene's first frame (read from her centre, ring-searched, in sight, never a stairwell), warms its figure on every spawn, intercepts its death before `resolveKills` so it earns no kill XP, and ends the contract on death or when the floor is won. `MercenaryRoster` (`src/core/party/MercenaryRoster.ts`) is the persisted contract, including the hire's live HP (`HiredMercenary.hp`) so walking through a door is not a free heal; a restore never brings back a contract signed on another floor.
- **Survival.** `src/creatures/mercenaries/hirelingSurvival.ts` holds the substance — half damage, the out-of-combat full heal, the bottomless cooldown-gated potion, and the downed/revive state — as constants and plain state; `Mercenary` and `MercenarySystem` only call into it. Half damage runs through `DamageLedger` (`src/creatures/damageLedger.ts`), the same fractional ledger `Mongo` uses at its own multiplier, applied in both `takeDamage` and `takeDamageFrom` so a status tick is softened too. At 0 HP a hire goes down instead of dying — `canBeHarmed` false, released from targeting, still in the mob grid so it renders — and waits out a revive window (`src/core/party/reviveRules.ts`, shared with a knocked-out crawler) before the contract ends for good. `MercenarySystem.dismissForTransition` is where a scene-leaving call site sends a hire that will not stand up again on the far side of the same walk — building entry/exit, recall, level complete — because a downed hire cannot be carried anywhere: it dies there instead. A tower's `changeFloor` is the one exception, since the hire is staying in the same building: it goes through `leaveStorey` (which resolves a downed hire the same way) and `carryCompanions`, which carries a standing hire across storeys and falls back to `dismissForTransition` only when it finds nowhere to land.
- **Indoors.** A hireling follows the party everywhere `BuildingInteriorScene` hosts them — shops, the club, safe rooms, every tower storey. A door dismisses it and the scene on the far side spawns a fresh one from the roster's saved HP; a tower's `changeFloor` instead carries a standing hire across storeys with `src/systems/companionCarry.ts`, alongside a summoned Mongo. It is exempt from the AI activation radius (`exemptFromAiActivationRadius`) like Mongo, so it keeps thinking while off screen, and `src/creatures/mercenaries/hirelingCatchUp.ts` snaps it back beside the party — out of sight and beyond `HIRELING_CATCH_UP_TILES`, or stuck for `HIRELING_STUCK_FRAMES` — rather than leaving it stranded. It is never pulled out of a fight of its own (`merc.isFighting`) or one a hostile with AI attention is holding it in.

### Adding a hireling

1. **Template.** Add the id to `MercenaryTemplateId` and an entry to `TEMPLATES_BY_ID` in `src/core/party/mercenaryTemplates.ts` (name, species, role, Rosemarie's pitch, price, hp, speed, damage, and the `kit`, `art`, `audioTag` and `voice` ids), and place it in `DESK_ORDER`. Every number is a named constant.
2. **Kit.** Reuse a kit by id, or add a `MercenaryKitId` and a class in `src/creatures/mercenaries/` implementing `MercenaryKit`, registered in `KIT_FACTORIES`. Land damage on the drawn impact frame, exported from the figure's timing module. If it fires projectiles, emit them through `drainProjectiles()` into the existing systems rather than a new one.
3. **Voice.** Add a `MercenaryVoiceId` and its `MERCENARY_VOICES` entry, with lines for every trigger the kit can fire.
4. **Figure.** Paint it through the four-file pipeline in the `bipedal-figure` skill (`src/sprites/art/<name>Art.ts`, `<name>Figure.ts`, `scripts/gates-<name>.ts`, `scripts/render-<name>.ts` plus its `render:` and `gates:` npm entries), with front, `_side` and `_away` views, the rows `idle`, `walk`, its attacks and specials, `hurt` and `death` (ending on a corpse frame), a timing module exporting each attack's impact frame, and the orange Meat Shields armband.
5. **Art entry.** Add a `MercenaryArtId` and its `MERCENARY_ART` entry. `prewarm` warms only what walking out of the club needs; the rows only a fight needs go in `prewarmForFight`. Set `gait` if the stride is authored against a distance, and `healthBarLiftTiles` if the head would sit under the bar. Hirelings hold no sheet keys — `companion:mercenary` in `systemAssetRequirements.ts` declares none — and only the hire under contract is ever warmed, so do not add the figure to a floor's groups.
6. **Audio.** If the `audioTag` is new, add its `case` to the `mob.audioTag` switch in `playMobAudioCues` (`src/systems/GameLoopPhases.ts`).
7. **Damage audit.** Add every new file that lands hireling damage to `HIRELING_DAMAGE_FILES` in `scripts/verify-tactics.ts`.
8. **Gate.** Write `scripts/verifyMercenaries/<kit>.ts` (it falls under the `scripts/verifyMercenaries/*.ts` include in `tsconfig.scripts.json`) measuring each special by its effect — HP moved, bodies displaced — never by counting casts, each rule paired with a run that must fail; call it from `scripts/verify-mercenaries.ts`. The shared checks in `verifyMercenaries/lifecycle.ts` (spawn, follow, leash, credit, friendly fire, survivability) and the hub's save and death checks iterate every template, so a new hire is covered by them automatically. Run `npm run verify:mercenaries`, `verify:tactics`, and `verify:friendly-fire`; `npm run verify:companions-indoors` covers following into buildings and tower storeys, and `npm run verify:hireling-loss` covers the circus assault and other rooms that can seal a hire away from the party.

Finish with the `dev-workflow` gates (typecheck, lint, format), plus `npm run verify:assets`, and `npm run verify:tactics` if the creature is tactics-eligible.

## Design debt

Before building on a system, check that file for entries about it and honour their **Until then** lines.
